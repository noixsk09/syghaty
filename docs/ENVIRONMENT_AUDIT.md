## 3. حالة مشروع `mo7ami-pro`

### ما هو موجود

- مشروع Next.js App Router أُنشئ عبر `create-next-app`
- TypeScript (`strict: true`)
- Tailwind CSS v4
- ESLint + `eslint-config-next`
- هيكل `src/app` مع صفحة افتراضية إنجليزية (قالب Next.js)
- `node_modules` مثبت (~271 حزمة مباشرة تحت الجذر)

### الإصدارات المثبتة فعليًا

| الحزمة | الإصدار |
| --- | --- |
| next | 15.5.4 |
| react / react-dom | 19.1.0 |
| typescript | 5.9.3 |
| tailwindcss | 4.3.3 |
| eslint | 9.39.5 |
| eslint-config-next | 15.5.4 |

### ما هو غير موجود بعد

- مستودع Git (لا يوجد مجلد `.git`)
- `package-lock.json` / أي lockfile
- ملفات `.env` أو `.env.local` أو `.env.example`
- Supabase / Zod / React Hook Form / Lucide / Recharts / Vitest / Playwright
- واجهة عربية RTL أو هوية محامي برو
- مجلد `supabase/` أو SQL migrations
- اختبارات
- أي منطق أعمال (عملاء، قضايا، مالية، …)

### ملاحظات تقنية مهمة

1. الواجهة الحالية إنجليزية (`lang="en"`) بخط Geist — ليست جاهزة للمنتج العربي.
2. `.gitignore` يتجاهل النمط `.env*` بالكامل، ما قد يمنع تتبع `.env.example` لاحقًا ما لم يُستثنَ صراحة.
3. سكربتات البناء تستخدم Turbopack (`next build --turbopack`) — مقبول للتطوير، ويُراجع لاحقًا للإنتاج.
4. لا توجد أسرار اتصال في المشروع حاليًا (صحيح وآمن في هذه المرحلة).

## 4. قرار المسار

**لا يُنشأ أي كود تطبيق داخل `C:\Windows\system32`.**  
كل أعمال Mo7ami Pro تتم داخل:

```text
C:\Users\____________________\mo7ami-pro
```

يُفضَّل فتح هذا المجلد كـ Workspace في Cursor قبل المرحلة 2.

## 5. عوائق يجب حلها قبل/أثناء المراحل التالية

| العائق | الأثر | الإجراء المطلوب من المستخدم |
| --- | --- | --- |
| Git غير مثبت | لا يمكن إدارة الإصدارات حسب المواصفات | تثبيت Git for Windows وإضافته إلى PATH |
| Workspace = system32 | خطر تعديل ملفات النظام / ارتباك المسارات | فتح مجلد `mo7ami-pro` في Cursor |
| لا يوجد مشروع Supabase | لا مصادقة ولا قاعدة بيانات بعد | إنشاء مشروع Supabase لاحقًا (المرحلة 3+) وتزويد المفاتيح عبر `.env.local` فقط |
| لا يوجد lockfile | تباين محتمل في الإصدارات بين الأجهزة | توليد `package-lock.json` عند أول تثبيت منظّم للاعتماديات |
